# Где брать сервер

Всё, что нужно проекту, — самый дешёвый VPS. Но адрес адресу рознь: половина
дешёвых серверов не годится не из-за железа, а из-за того, что их подсеть уже
заблокирована. Поэтому проверка адреса важнее выбора тарифа.

## Что заказывать

| Параметр | Минимум | Почему так |
|---|---|---|
| Процессор | 1 ядро | считать нечего, весь трафик просто пересылается |
| Память | 1 ГБ | своп на 2 ГБ роль создаёт сама, от нехватки страхует |
| Диск | 10 ГБ | образы Docker и логи, больше не нужно |
| ОС | Ubuntu 22.04/24.04 или Debian 12 | на них проект и проверялся |
| Трафик | чем больше, тем лучше | видео съедает быстро; «безлимит» часто режется после порога |
| IPv4 | **выделенный** | за общим адресом (NAT) не поднять ни один сервис |
| IPv6 | желателен | нужен для второго DNS-туннеля (dnstt), без него он не встанет |

Доступ — по SSH под `root`. Если хостер даёт вставить свой SSH-ключ при
создании — вставьте `keys/vpn-infra.pub`, это избавит от возни с паролем.

## Как выбрать страну и хостера

**Задержка почти не зависит от страны в пределах Европы.** Замер с юга России:
Литва 32 мс, Финляндия 33, Швеция 35, Латвия 37 — разница незаметна на глаз.
Свою задержку до разных регионов можно прикинуть на [cloudping.info](https://cloudping.info/).

**Зависит она от хостера и его сети (AS).** Крупные площадки популярны и у тех, кто
рассылает спам и держит ботнеты, — их подсети чаще попадают под ковровые
блокировки целиком. Известный пример: к адресам зарубежных дата-центров
российские операторы пропускают около 25 пакетов и дальше замораживают
соединение; [Cloudflare подтверждал это официально](https://blog.cloudflare.com/russian-internet-users-are-unable-to-access-the-open-internet/)
для Hetzner, DigitalOcean и OVH. Лечится это только сменой хостера.

Отсюда два правила:

1. **Второй сервер держите у другого хостера, в другой стране и другой AS.** Ляжет
   подсеть — переезд занимает минуты (порядок описан в [SERVER.md](SERVER.md#если-сервер-заблокировали)).
2. **Не берите сразу на год.** Возьмите месяц, проверьте адрес в деле, и только
   потом продлевайте надолго.

## Проверить адрес до деплоя

Блокировка адреса бывает двух видов:

- **полная** — из российских сетей не проходит даже TCP-соединение;
- **мягкая** — соединение открывается, а данные пропадают: TLS висит, SSH-баннер не
  приходит, UDP не доходит совсем. Так 26.09.2026 закрыли прошлый сервер на Veesp.

Мягкую не видят ни `nc -vz <адрес> 443`, ни «TCP connect» в онлайн-чекерах: соединение
есть — значит «успешно». Засчитывать можно только ответ самого сервера.

Порядок, от дешёвого к точному. Скрипты — в `tools/measure/`, подробнее в [MEASURE.md](MEASURE.md).
Вместо `203.0.113.10` подставьте свой адрес, скриптам можно передать несколько сразу.

1. **История адреса**: `curl https://internetdb.shodan.io/203.0.113.10`. Чужие открытые
   порты — адрес уже кому-то служил, возможно под VPN. Чистая история ничего не обещает:
   большинство заблокированных адресов HostVDS были без неё.
2. **Быстрый отсев**: `python3 tools/measure/ru-reach.py --fast 203.0.113.10` — TCP-соединение
   с узлов check-host в Москве и Петербурге. Ловит только полную блокировку.
3. **Домашние сети РФ**: `python3 tools/measure/ru-reach.py 203.0.113.10` — SSH-баннер с 12
   домашних провайдеров через Globalping. Годен адрес, где данные пришли хотя бы на 90%
   проб. Одна-две неудачи бывают у самих проб: перепроверить.
4. **UDP** для WireGuard: запустить на сервере `probe-responder.py`, затем
   `ru-reach.py --port 80 --udp 203.0.113.10`. Мягкая блокировка режет UDP там же, где
   TCP-данные.
5. **Свой провайдер**, пока работает ответчик: открыть `http://<IP>` с телефона без VPN —
   по домашнему Wi-Fi и с мобильного. Строка `OK <IP> <время>` — данные проходят.
   Своего провайдера среди проб Globalping может не оказаться, поэтому шаг решающий.

Пустят ли с адреса зарубежные сервисы (Netflix, ChatGPT) и каким регионом его считают:

```bash
bash <(curl -Ls IP.Check.Place) -l en
bash <(wget -qO- https://ipregion.vrnt.xyz)
```

Берите хостеров с почасовой оплатой: неудачный адрес удаляется за копейки. У остальных
до оплаты спросите, меняют ли адрес при блокировке из РФ, — Veesp и is\*hosting отказывают.

## Перебор адресов

Блокируют адреса поштучно, и у одного хостера выжженные подсети соседствуют с чистыми.
Поэтому искать «хороший хостер» мало — нужен хостер с почасовой оплатой, где адреса
перебираются: создать пачку серверов, отсеять, оставить один, остальные удалить.

**Новый сервер создавать до удаления старого.** Освободившийся адрес возвращается в пул,
и следующему заказу может достаться он же.

### HostVDS через API

Панель выдаёт адреса из нескольких подсетей Риги: 27.09.2026 ни один из 11 выданных ею
адресов из РФ не работал. Через OpenStack API доступны все сети всех регионов, в том числе
регионов, которых панель не показывает. Отсев того же дня, TCP с узлов check-host в РФ:

| Регион API | Где | Прошли |
|---|---|---|
| eu-north1b, eu-north2 (из них раздаёт панель) | Рига | 0 из 20 |
| eu-north1, сети `Unlisted-*` | Рига | 2 из 10 |
| eu-west1, сети `Unlisted-*` | Амстердам | 7 из 7 |
| eu-west2 | Чехия | 4 из 11 |
| eu-west3 | Амстердам | 1 из 3 |

Прошедшие из eu-west1 и eu-north1 потом прошли и домашние сети РФ, и UDP. Сети
`RESERVE-*` снаружи не отвечают вовсе.

```bash
export OS_USERNAME=... OS_PASSWORD=...    # панель HostVDS → раздел API
IPS=$(python3 tools/hostvds.py create eu-west1 --count 9)
python3 tools/measure/ru-reach.py --fast $IPS
python3 tools/measure/ru-reach.py <прошедшие отсев>
python3 tools/hostvds.py delete-probes --keep <победитель>
python3 tools/hostvds.py rename <победитель> vpn-xxx
python3 tools/hostvds.py resize <победитель> hostvds-2
```

Грабли:

- квота — 10 серверов на **регион**, а не на аккаунт;
- сервер без группы безопасности `allow_all` снаружи не отвечает никому и выглядит
  заблокированным; `hostvds.py` добавляет её сам;
- шлюз API временами отвечает 504 — повторить;
- `hostvds-1` гарантирует 1/10 ядра и 0,5 ТБ трафика на 50 Мбит/с: для перебора хватает,
  рабочий сервер переводить на `hostvds-2` (2 ГБ, 1 ТБ на 1 Гбит/с, сверх — €1 за ТБ);
  тариф канала меняется в панели, смена тарифа сервера адрес не меняет.

Около 60 проб за вечер обошлись меньше чем в €0,2.

С другим хостером схема та же: почасовая оплата плюс API или кнопка «новый адрес»
(Timeweb Cloud — до 10 адресов в сутки). Проверка — те же `ru-reach.py`, создание
серверов пишется под API хостера.

## Домен: нужен не всем

WireGuard и Reality работают по голому адресу — домен для них не обязателен.
Он нужен в двух случаях.

**Для DNS-туннелей — обязателен**, причём с возможностью заводить NS-записи.
Требования к имени и порядок делегирования — в [TUNNEL.md](TUNNEL.md#домен).
Коротко: имя покороче, без слов `vpn`, `proxy` и `tunnel`, и **не в зоне `.ru`** —
там нужны паспортные данные, а разделегирование по решению реестра убьёт все
туннели разом, даже при живых серверах.

**Для WireGuard — удобен.** Если клиенты подключаются к имени, а не к адресу, то
при переезде на другой сервер достаточно поменять A-запись: конфиги, которые уже
у людей на руках, продолжат работать.

Если у регистратора нет NS-записей (так, например, у Timeweb) — переведите DNS
в Cloudflare на бесплатном плане и пропишите его серверы имён у регистратора.
Отдавать регистратору весь домен на свой сервер не стоит: падение сервера убьёт
домен целиком.

## Держите про запас

Готовое заранее превращает аварию из вечера в пять минут:

- **второй поддомен уже делегирован** — делегирование расходится часами;
- **свежий `make backup`** — с ним новый сервер поднимается с теми же ключами;
- **проверенный резервный хостер** — знать, где брать замену, лучше, чем искать
  её в момент, когда всё лежит;
- **запасной сервер с уже проверенным адресом** — у HostVDS самый младший тариф
  стоит около €1,5 в месяц, а новый чистый адрес потом ищется вечер.

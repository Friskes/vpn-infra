# Эксплуатация серверов

Всё, что нужно знать после первого `make deploy`: секреты, несколько серверов, переезд
при блокировке и грабли, на которые уже наступали.

## Доступ

Зайти на сервер: `make ssh` (или `make ssh HOST=<имя>`, если серверов несколько).
Вход только по SSH-ключу из `keys/` — пароль отключён (`ssh_disable_password: true`).
Роль откажется отключать пароль, пока на сервере нет ни одного ключа, так что одной
опечаткой отрезать себе доступ не выйдет.

**Потеряете `keys/vpn-infra` — попадёте на сервер только через аварийную консоль хостера**
(Console, VNC или KVM в панели). Стоит один раз проверить, что она открывается, и сделать
копию ключа в надёжном месте.

Первый заход на новый VPS: вставить `keys/vpn-infra.pub` в панели хостера при создании
или один раз выполнить `make ssh-key HOST=<имя>` — он спросит root-пароль из письма
хостера и положит ключ. Старый путь тоже работает: root-пароль в `vault_ssh_password` в
`host_vars/<имя>/vault.yaml`, на ПК тогда нужен `sshpass`.

## Секреты

Пароли админок придумывает `make init` — случайные, по 32 символа. Запоминать их не
нужно: в админки заходят через SSH-проброс, а посмотреть пароль можно в любой момент.

```bash
make show-secrets   # показать пароли, ничего не меняя
make edit-secrets   # поправить прямо в зашифрованном файле
```

Пароль от самого vault лежит в `.vault-key` в корне проекта, один на все серверы, в git
не попадает. **Потеряете — vault не расшифровать**, сделайте копию в надёжном месте.
Ansible берёт ключ сам, вводить ничего не нужно.

Если удобнее править файл целиком обычным редактором:

```bash
make decrypt   # расшифровать все vault-файлы
make encrypt   # зашифровать обратно
```

Держать их расшифрованными тоже можно: vault-файлы в `.gitignore`, а проверка перед
коммитом ловит только открытый файл, попавший под git. Защита на диске при этом
условная и в зашифрованном виде: `.vault-key` лежит рядом.

`ping`, `check` и `deploy` ключ сами не создают, а останавливаются с подсказкой: иначе
потерянный ключ подменился бы новым, и ошибка выглядела бы как «Decryption failed».

`make hooks` включает проверку перед каждым коммитом: не попали ли под контроль версий
открытый vault, `.vault-key`, ssh-ключ и инвентарь, плюс gitleaks, yamllint,
ansible-lint и shellcheck. CI в проекте нет намеренно — это единственное место, где всё
проверяется, поэтому хуки стоит поставить сразу.

## Несколько серверов

Каждый живёт сам по себе: свой домен туннеля, свои ключи, свои клиентские конфиги.
Заблокируют один — остальные работают.

```bash
make new-host NAME=vpn-nl IP=203.0.113.10   # настройки нового сервера и запись в инвентаре
make hosts                                  # список
make deploy HOST=vpn-nl                     # развернуть только его
```

Ограничения `HOST=` и `TAGS=` работают для любой команды и комбинируются:
`make deploy HOST=vpn-nl TAGS=wireguard` тронет один сервис на одном сервере. Теги
совпадают с именами ролей: `swap`, `common`, `ssh`, `docker`, `firewall`, `fail2ban`,
`wireguard`, `slipstream`, `dnstt`, `xui`, `rustdesk`, `summary`.

Прочее: `make ping` — есть ли связь, `make check` — сухой прогон (что изменится, ничего
не меняя), `make upgrade` — деплой плюс обновление пакетов, `make backup` — снять
состояние в `artifacts/`, `make help` — все команды.

| Файл | Что задаёт | В git |
|---|---|---|
| `inventory/hosts.yaml` | список серверов и их адреса | нет |
| `host_vars/ИМЯ/vars.yaml` | набор сервисов, домен туннеля и резолвер — **свои у каждого** | нет |
| `host_vars/ИМЯ/vault.yaml` | SSH-пароль этого сервера; свои пароли админок, если нужны | нет |
| `group_vars/all/vars.yaml` | общее для всех, в том числе набор сервисов по умолчанию | да |
| `group_vars/all/vault.yaml` | общие пароли админок (SSH-пароль здесь не хранить) | нет |

**Домен туннеля обязан быть свой у каждого сервера**: один поддомен на два сервера не
заработает, резолверы будут получать два разных ответа на один вопрос.

Пароли админок по умолчанию общие. Отдельный пароль серверу — раскомментировать
`vault_wireguard_admin_password` или `vault_xui_admin_password` в его `vault.yaml`: тогда
утечка одного сервера не откроет остальные.

SSH-пароли серверов не являются общими. Для каждого хоста задайте `vault_ssh_password`
в `host_vars/<имя>/vault.yaml` и зашифруйте файл командой `make encrypt`. Если старый
пароль лежит в `group_vars/all/vault.yaml`, удалите его оттуда после переноса. Каталог
`group_vars/<имя>` для этого не подходит: Ansible считает его переменными группы, а не
переменными конкретного хоста.

**Набор сервисов задаётся выключателями** — общий в `group_vars/all/vars.yaml`, для
отдельного сервера переопределяется в его `vars.yaml`: `wireguard_enabled`,
`xui_enabled`, `slipstream_enabled`, `dnstt_enabled`, `rustdesk_enabled`. Выключенный
сервис гасится, а порт файрвол не откроет. Открытые прежде правила ufw роль не
удаляет — убирать руками (`ufw delete allow <порт>/tcp`).

## Доступ к админкам

Режим задаёт `admin_public`: для всех серверов — в `group_vars/all/vars.yaml`, для одного —
в его `host_vars/<имя>/vars.yaml`.

**`false` (по умолчанию) — админки только на loopback сервера.** Снаружи их нет, из VPN
тоже. Вход — через SSH-проброс, его открывает `make admin` (`HOST=<имя>` для не первого
сервера): печатает адреса и пароли и держит проброс, пока окно открыто.

- `http://127.0.0.1:15821` — wg-easy: создать клиента, скачать конфиг или снять QR-код;
- `http://127.0.0.1:15831` — панель AmneziaWG, если он включён: логин `admin`, пароль как у wg-easy;
- `http://127.0.0.1:2053/<путь>/` — панель Xray, путь случайный, `make admin` его покажет.

Локальный порт wg-easy — 15821, а не 51821, как на сервере: из диапазона 49152–65535
Windows при загрузке резервирует куски под Hyper-V, и проброс из WSL на таком порту
молча не работает. Другие порты — `WG_LOCAL=… XUI_LOCAL=… make admin`.

Постоянный проброс удобнее описать в `~/.ssh/config` — те же порты, `ssh vpn` вместо
`make admin`:

```sshconfig
Host vpn
    HostName <IP сервера>
    User root
    IdentityFile ~/vpn-infra/keys/vpn-infra
    LocalForward 15821 127.0.0.1:51821
    LocalForward 15831 127.0.0.1:51831
    LocalForward 2053 127.0.0.1:2053
```

**`true` — админки открыты в интернет**: `http://<IP сервера>:51821` и
`http://<IP сервера>:2053/<путь>/` прямо из браузера, без SSH. Включайте, если проброс
неудобен и риски ниже вас устраивают:

- админки работают по HTTP, и пароль уходит по сети открытым текстом — его может прочитать
  провайдер или сосед по открытому Wi-Fi;
- wg-easy на порту 51821 находят сканеры вроде Censys (он обходит все порты), и по их базам
  сервер ищется как VPN;
- у wg-easy нет защиты от перебора (чем это грозит — ниже): её держит только длинный случайный
  пароль из `make init`. Панель Xray перебор режет сама: после 5 неверных паролей за 5 минут
  вход с этого адреса закрывается на 15 минут.

Проброс работает и при `true`: так пароль не идёт по сети открытым текстом.

**Смена режима пересоздаёт контейнеры wg-easy, AmneziaWG и 3x-ui** — VPN и Reality пропадут на
несколько секунд, поэтому сначала `make check`. Открытым админкам роль firewall прописывает порт и в ufw:
иначе они не открывались бы из своего VPN и по IPv6 — такие обращения докер принимает через
INPUT. При возврате на `false` эти правила остаются, роль их не удаляет — убрать руками:
`ufw delete allow 51821/tcp`, `ufw delete allow 51831/tcp` и `ufw delete allow 2053/tcp`.

**Проброс разрешён не куда угодно.** В `sshd` стоит `PermitOpen` ровно на эти порты (список
собирается в `ssh_permit_open` по включённым сервисам), поэтому `-L` на любой другой порт
молча оборвётся — без единой записи в логах. Добавите сервис с админкой на loopback —
впишите его порт туда же, иначе потеряете вечер.

**Адрес `10.8.0.1:51821` закрыт в обоих режимах.** Раньше по нему админку открывал любой,
кому выдан конфиг, и это было удобно ровно до первого вопроса «а что он там может».
А может он много: счётчика попыток пароля у wg-easy нет вовсе, перебирать можно прямо через
API, а `GET /api/wireguard/backup` отдаёт ключи всех клиентов разом. То есть один выданный
конфиг плюс подобранный пароль — и у человека ключи остальных. Запрет ставится правилом в
`wireguard_post_up`, там же закрыт доступ из туннеля к docker-сетям, через которые была
достижима панель Xray. У AmneziaWG так же закрыт `10.9.0.1:51831`: правила роль `awg` задаёт
через API панели и сверяет каждый прогон.

## AmneziaWG

WireGuard с маскировкой от DPI: у пакетов другие заголовки и размеры, перед рукопожатием идёт
мусор. Нужен там, где провайдер рвёт обычный WireGuard сразу после рукопожатия — так 29.09.2026
было у Ростелекома, см. [MEASUREMENTS.md](MEASUREMENTS.md).

Роль `awg` ставит рядом с wg-easy второй контейнер — wg-easy v15.4 в режиме AmneziaWG. У него
свои клиенты, своя панель и свой UDP-порт, обычный WireGuard и его конфиги не трогаются.
Включить на сервере, в `host_vars/<имя>/vars.yaml`:

```yaml
awg_enabled: true
awg_vpn_port: 28824   # любой свободный UDP-порт, лучше вне 32768–60999
```

Потом `make deploy HOST=<имя> TAGS=docker,ssh,firewall,awg,summary` — остальные контейнеры
не пересоздаются. Приложение у клиентов — AmneziaWG ([CLIENTS.md](CLIENTS.md#amneziawg)):
обычный WireGuard такой конфиг не откроет.

Что стоит знать:

- модуль ядра не нужен: в образе есть программная реализация `amneziawg-go`, на сервере
  ничего не собирается;
- при первом запуске контейнер создаётся с паролем в переменных `INIT_*` и сразу
  пересоздаётся без них, чтобы пароль не остался в `docker inspect`;
- правила iptables, keepalive 25 с и DNS роль задаёт через API панели под паролем wg-easy.
  Сменили его в vault — поменяйте и в панели AmneziaWG, иначе роль не войдёт;
- `make backup` снимает базу панели в `artifacts/<сервер>/awg-easy.db`, переезд —
  `-e awg_restore_src=artifacts/<старый>`.

## Если сервер заблокировали

Главная угроза — ковровая блокировка префикса хостера: ляжет и VPN, и DNS-туннель
(резолвер оператора ходит за ответом на тот же адрес). Защита — быстро поднять новый VPS
у другого хостера, в другой стране и AS.

Заготовить заранее, чтобы переезд занял минуты:

- **второй поддомен уже делегирован**: `t2` (NS → `ns2.<домен>`) и `ns2` (A → любой
  временный адрес). Делегирование расходится часами, ждать его в момент аварии — терять
  время; A-запись потом поправите;
- **свежий `make backup`** — состояние wg-easy и учётки туннеля в `artifacts/<сервер>/`.
  С ним новый сервер поднимается с теми же ключами, и конфиги, которые уже у людей на
  руках, продолжают работать. Снимать после каждого заведения клиента.

Порядок:

1. Взять VPS у другого хостера (другая страна и AS) и проверить адрес по
   [HOSTING.md](HOSTING.md#проверить-адрес-до-деплоя).
2. `make new-host NAME=vpn2 IP=<новый IP>`, вписать в `inventory/hosts.yaml`.
3. A-запись `ns2` → новый адрес.
4. В `host_vars/vpn2/vars.yaml` — домен `t2.<домен>`, резолвер, `wireguard_host`.
5. `make deploy HOST=vpn2 ARGS="-e wireguard_restore_src=artifacts/vpn1/wg-easy-state.tar.gz"`
   — только новый сервер, боевой не трогаем.
6. Перевести A-запись имени из `wireguard_host` на новый адрес: клиенты подхватят его,
   когда переподключат туннель. Старый сервер погасить.

Если старый сервер уже под мягкой блокировкой, SSH к нему из дома не проходит —
`make backup` снимать, пока ПК выходит в интернет через зарубежный VPN.

Восстановление разворачивается только там, где своего состояния ещё нет, — рабочий сервер
случайным запуском не затрёшь. Ссылки туннеля выпускаются заново командой `slipnet-user`:
в них зашит домен, а он у каждого сервера свой.

**Старый сервер умер насовсем** — переезжает всё, и клиентам ничего править не нужно,
если они подключаются по имени (`wireguard_host`), а не по IP. Шаги 3–4 меняются: в
`vars.yaml` нового сервера — прежние `slipstream_domain` и `dnstt_domain`, а к деплою
добавить восстановление из бэкапа старого:

```bash
make deploy HOST=vpn2 ARGS="-e wireguard_restore_src=artifacts/vpn1/wg-easy-state.tar.gz \
  -e slipstream_restore_src=artifacts/vpn1 -e dnstt_restore_src=artifacts/vpn1 \
  -e xui_restore_src=artifacts/vpn1 -e awg_restore_src=artifacts/vpn1 -e rustdesk_restore_src=artifacts/vpn1"
```

Переносятся клиенты wg-easy и AmneziaWG, учётки и ключи туннелей, база 3x-ui вместе с путём
панели, ключ RustDesk. Потом перевести на новый сервер A-записи имени из `wireguard_host` и `ns`,
AAAA-запись `ns6`. Так 27.09.2026 всё переехало с заблокированного Veesp: резолвер МТС до
него не доставал, через Яндекс было 15 КБ/с.

**Куда переезжать** и как проверить свежий адрес до оплаты — в [HOSTING.md](HOSTING.md).
Коротко: другой хостер, другая страна, другая AS.

## Грабли, на которые уже наступали

- **Образы пинятся по версии** (`wg-easy:14`, `rustdesk-server:1.1.16`), `latest` не
  используется. wg-easy держим на v14: v15 переписан на веб-мастер и падает при заданном
  `PASSWORD_HASH`.
- **Деплой не перезагружает сервер сам** и не ставит обновления пакетов — этим занимается
  unattended-upgrades, с автоперезагрузкой в 04:30, если она нужна. Разово:
  `make deploy ARGS="-e common_auto_reboot=true"` и `make upgrade`.
- **Прогон нельзя прерывать** в ролях wireguard и rustdesk: контейнер пересоздаётся как
  «удалить старый → создать новый», обрыв посередине оставит сервис лежать.
- **Правила ufw только добавляются**, никогда не удаляются: лишнее убирать руками
  (`ufw delete allow <порт>/tcp`).
- **Портами ufw контейнеры Docker не закрыть**: Docker разворачивает трафик через DNAT в
  цепочке FORWARD, а ufw живёт в INPUT. По той же причине fail2ban не прикроет админку —
  баны пишутся в INPUT, а wg-easy к тому же не логирует неудачные входы.
- **Хэш пароля админки кэшируется** в `/root/.wg-easy.hash-<отпечаток>`: соль bcrypt
  случайная, без кэша каждый прогон пересоздавал бы контейнер. Смена пароля в vault меняет
  отпечаток, и хэш пересчитывается сам.
- **Своп создаётся ролью `swap`** (2 ГБ) и идёт первой: на машине с гигабайтом памяти он
  страхует от OOM во время apt-апгрейда.

## Безопасность

- **SSH — только ключ**, проброс портов закрыт, кроме локального `-L` на админки: список
  портов собирается в `ssh_permit_open` по включённым сервисам (wg-easy, панели AmneziaWG
  и Xray). Проброс unix-сокетов запрещён отдельно — через него доставали сокет докера.
  Раньше форвардинг был открыт целиком, и через него плюс пароль общей учётки вскрывалась
  админка.
- **Админки по умолчанию не смотрят ни наружу, ни в VPN** — только loopback сервера и
  SSH-проброс. Открыть их в интернет можно флагом `admin_public`, о рисках — см.
  [«Доступ к админкам»](#доступ-к-админкам).
- **Пользователи туннеля до сервера не достают**: в конфиге прокси `deny` на loopback и
  частные сети. Проверить после правок в роли — зайти через туннель на `127.0.0.1:51821`,
  должно быть отказано.
- **Никаких учёток «только для туннеля»** — почему, написано в [TUNNEL.md](TUNNEL.md).
- **Секреты только в vault-файлах**, приватный ключ — в `keys/`, всё мимо git.
- После развёртывания проверить баны: `fail2ban-client status sshd`. Loopback fail2ban
  не банит, доступ изнутри сервера он не ограничивает.
